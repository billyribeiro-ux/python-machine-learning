TA-Lib Mastery

TA-Lib wraps 150+ battle-tested C indicators. We learn to use them correctly — and to wrap them in our own engine so they obey the QuantLab contract.

What this lesson will cover

Why TA-Lib (and its one big gotcha)

The C library is fast and canonical, but every function has a warmup period that returns NaN, and input order/length matters. We map the failure modes.

The function families

Overlap studies (SMA/EMA/BBANDS), momentum (RSI/MACD/STOCH/ADX), volume (OBV/AD), volatility (ATR/NATR), pattern recognition (candlesticks), and cycle indicators — with a copy-paste cheat-sheet for each.

The abstract vs function API

talib.RSI(close) vs talib.abstract.Function('RSI') — when the abstract API's introspection (inputs, parameters, output names) makes generic, settings-driven code possible.

Wrapping TA-Lib in our engine

Adapter functions that take our normalized OHLCV frame, call TA-Lib, and return aligned columns with honest NaN warmup — so TA-Lib indicators drop into the same pipeline as our NumPy ones.

Validating against our from-scratch versions

Cross-check talib.RSI/SMA/ATR against quantlab.indicators to build trust in BOTH implementations (this is exactly what tests/test_indicators.py already does for RSI and SMA).

🧱 Already in the repo

The reusable building blocks for this module live in the quantlab/ package (data layer, indicators, backtest + stats engine, strategy combiner) and are exercised by the tests/ suite. The lesson narration will show you how they were built and how to extend them.
