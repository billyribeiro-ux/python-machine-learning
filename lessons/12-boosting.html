XGBoost & LightGBM Alpha

Gradient-boosted trees are the workhorse of tabular alpha: they capture nonlinear feature interactions, shrug off feature scaling, and give strong baselines fast. We train them honestly (time-ordered, early-stopped), interpret them with importance/SHAP, and — the only test that counts — backtest their predictions.

1. Why boosted trees for market features

Our features (RSI, z-score, ATR ratios, momentum) interact nonlinearly: "high RSI" means different things in a low-volatility uptrend vs a choppy range. Tree ensembles model those interactions automatically, need no scaling, handle monotonic and threshold effects naturally, and train in seconds. On tabular financial data they routinely beat neural nets — and they're far easier to validate.

2. Training, the honest way

Our quantlab.ml.models wrappers bake in the discipline: a chronological train/test split (never random — that leaks the future), early stopping on the held-out set, and predictions returned as probabilities so position sizing is a separate, testable decision.

Expected output (numbers vary)

=== XGBoost === accuracy=0.543 auc=0.546 OOS: return=22.0% sharpe=0.46 maxDD=-7.7% === LightGBM === accuracy=0.538 auc=0.522 OOS: return=47.2% sharpe=1.00 maxDD=-7.7% Top features: ['atr_14(56)', 'ret_20(34)', 'rsi_14(33)', 'sma_50(31)', 'std_20(27)']
⚠️ Early stopping must use a time-ordered set

Early stopping picks the number of trees by watching a validation score. If that validation set is a random sample, the model tunes itself using future bars — a leak that inflates every metric. Our wrappers split chronologically and early-stop on the last slice. Small detail, enormous consequence.

3. Interpretation: importance and SHAP

Feature importance (gain/split counts) tells you which features the model leans on; SHAP values tell you how each feature pushed each individual prediction up or down — and are the best tool for catching a "feature" that's secretly a leak (e.g. a column that's implausibly predictive).

4. Predictions to positions

A classifier outputs P(up). Turning that into a position is a separate decision with real consequences. Going long only when the model is confident (P > 0.55, not merely > 0.5) trades less, pays fewer costs, and is more robust to a noisy classifier — which is exactly what proba_to_signal does before the backtest engine applies the one-bar execution delay.

🧱 The full, honest stack

Registry features → volatility-scaled triple-barrier labels → time-ordered split with early stopping → confidence-gated signal → leak-free backtest with costs. Every link was built and tested in earlier modules. That end-to-end integrity — not any single model — is what makes results you can stake capital on.

🛠️ Try it

Sweep long_th from 0.50 to 0.65 and plot out-of-sample Sharpe vs threshold. You'll typically see a sweet spot: too low and you trade noise; too high and you barely trade. Then add a short leg (go short when P < 0.45) and compare. You're now tuning the policy, not just the model.
