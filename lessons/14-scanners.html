Module 14 · Putting It Together

Multi-Symbol Scanners

A scanner is the tool you open every morning: point it at a universe and it ranks the names matching your setup. We combine the data layer, the indicator library, and cross-sectional ranking into reusable scanners for swing and day-trade setups — the same code, any timeframe.

1. Scanner architecture

The pipeline is always the same: pull a tidy multi-symbol panel through the provider → compute per-symbol indicators (grouped, so AAPL never bleeds into MSFT — the Module 2/3 rule) → take the latest row per symbol → apply a filter (the setup) and a ranking. Our quantlab/scanners/scanner.py implements exactly this, with named, composable setups.

2. Setups as composable predicates

A "setup" is just a function from the snapshot to a boolean mask, so they compose with & / |. QuantLab ships five snapshot setups plus an intraday one — each requires minimum dollar volume, because you never scan into names you can't actually trade:

SetupFinds
swing_pullbackuptrend, RSI cooled to 40–55 (buy the dip)
momentum_breakoutstretched above the mean (z>1), strongly trending
relative_strengthRS line vs SPY at a new high with positive RS momentum (market leaders)
gap_upopened >2% above prior close, above the 50-day (gap-and-go)
new_high_breakoutat/near the 52-week high with positive momentum
opening_range_breakoutintraday: broke above the first-30-min high (own pipeline)

The first five operate on the daily snapshot; relative_strength additionally needs a benchmark (defaults to SPY) and the snapshot adds the RS columns automatically.

4. Cross-sectional ranking

Filtering tells you which names qualify; ranking tells you which first. For a fair comparison across very different stocks, rank on scale-free quantities (momentum %, z-score, relative strength vs SPY) rather than raw price or dollar moves. For a true cross-sectional score, z-score each feature across the universe on the snapshot day, then sum — so "top 10" means comparably strong on every dimension.

🔬 Scanners ride the data lake

For large universes, don't re-download every run — scan over the DuckDB data lake from Module 4. The per-symbol window indicators can even be computed in SQL (OVER (PARTITION BY symbol ...)) or in Polars with .over("symbol") for a parallel pass. The scanner logic is identical; only the data source changes — the payoff of building on the data foundation.

5. Intraday / day-trade scanning

The snapshot setups become day-trade tools just by switching the timeframe: scan(provider, universe, timeframe="5m", start=...). Some setups, though, need intra-session structure — so they get their own pipeline. The opening-range breakout is the canonical example: it measures the high/low of the first 30 minutes, then flags names that later trade above that range.

Yahoo serves only ~60 days of intraday data, and for serious day trading you'd plug in a real-time provider behind the same interface — one of the reasons we built the data layer the way we did.

6. End-to-end testing every scanner

Two things guard the scanners. code/m14_scanners_e2e.py auto-discovers every scanner, runs each against a live ~40-symbol universe, and validates the results — every hit must truly re-satisfy its setup, the ranking must be ordered, the liquidity floor respected, and no NaNs in the output. tests/test_scanners.py is the offline, deterministic twin (seeded synthetic data, including an intraday provider for ORB) so CI checks every scanner on each push. Add a new scanner and both harnesses pick it up automatically.

🛠️ Try it

Add a relative_strength setup that flags names whose ratio to SPY is making a new 60-day high (join each symbol's close to SPY's, as in Module 4's SQL). Combine it with swing_pullback using & to get "strong-vs-market pullbacks" — a classic, high-quality swing screen.
