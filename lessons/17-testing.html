Module 17 · Putting It Together

Testing & Quality at Scale

The habit that makes everything else trustworthy. We turn correctness into automated guarantees: known-value indicator tests, property-based tests over random inputs, backtest invariants that catch look-ahead, and a regression on the combined-indicator stats — so a refactor can never silently change your edge.

1. Why testing is non-negotiable in quant

In most software a bug throws an error. In quant, a bug usually returns a plausible wrong number: an off-by-one rolling window, a look-ahead shift, an axis flipped. The code runs, the chart looks fine, and you trade a lie. Tests are how you make wrong-but-plausible impossible. Every indicator and backtest in QuantLab has a test that fails loudly the day its behavior changes.

2. Known-value & cross-implementation tests

The simplest guarantee: our indicators must match an independent reference. tests/test_indicators.py compares our NumPy indicators to pandas, to a hand-written O(n·w) reference, and — when installed — to TA-Lib. NaN warmup regions are masked out of the comparison (they're correct, not bugs).

🔬 importorskip = honest optional deps

TA-Lib needs a C library not everyone has. pytest.importorskip ("talib") turns "TA-Lib missing" into a skip, not a failure — so the suite is green on a minimal install and still validates against TA-Lib wherever it's present. Optional dependencies should degrade gracefully in tests exactly as they do in code.

3. Property-based testing with Hypothesis

Example-based tests check the cases you thought of. Property tests check invariants over thousands of random inputs Hypothesis generates for you — and when one fails, it shrinks the input to a minimal counterexample. The invariants below must hold for any price series, which is a far stronger statement than "works on AAPL."

🧱 The no-look-ahead property is the crown jewel

test_zscore_no_lookahead encodes the rule that has run through this entire course as a machine-checked property: the indicator's value at past bars must not change when you add or remove future bars. If a refactor ever introduces a peek, Hypothesis will find a series that exposes it. You can — and should — assert this for every indicator you write.

4. Backtest invariants

tests/test_strategy_stats.py guards the engine itself with properties that any correct backtest must satisfy:

  • One-bar execution delay — an always-long signal earns the asset's return shifted by one bar (proves no peeking).
  • Costs only reduce returns — turning on fees can never increase total return.
  • Drawdown ≤ 0, win rate ∈ [0,1], and the equity curve reconciles with total return.
  • Settings actually bite — different ComboParams must produce different positions (else the parameters aren't wired in).

5. Regression-test the combined-indicator stats

The capstone: combine multiple indicators with custom settings, run the leak-free backtest, and pin the resulting stats on fixed synthetic data. Now any change that alters the numbers fails the test — you'll know immediately whether a "harmless" refactor moved your edge. This is the user's original goal, frozen into a guardrail.

🔬 Fast, offline, deterministic

tests/conftest.py synthesizes OHLCV with a seeded generator and serves it through a FakeProvider — so the whole suite runs without a network, gives the same answer every time, and finishes in seconds. That's what lets you run it on every save and in CI: a slow or flaky suite is a suite people stop running.

6. CI & coverage

  • Run pytest -q on every push (GitHub Actions: a few lines of YAML). Green-on-merge is the contract.
  • Gate heavy/optional deps with importorskip so CI stays fast and doesn't require TA-Lib's C library.
  • Track coverage, but value the right tests (invariants, no-look-ahead, stats reconciliation) over a coverage percentage.
🛠️ Try it

Write a Hypothesis property for atr: for any high≥low≥0 arrays, ATR must be ≥ 0 and never exceed the maximum true range seen so far. Then add a no-look-ahead property for rsi (truncating the future must not change past values). Run pytest -q and watch your guarantees grow.
