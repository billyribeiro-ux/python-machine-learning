Module 7 · Indicators

Build a Better Indicator Library

The payoff module: a unified Indicator base class + registry + custom-settings system that works across pandas, Polars, and Numba — so any indicator composes, sweeps, and tests uniformly.

🚧 Full lesson in progress

The course is being written module-by-module for maximum depth. This lesson's detailed outline is below so you can see exactly what it will cover — and the underlying quantlab package code it builds on already exists and is tested. Modules 0–4 are complete and runnable; work through those first.

What this lesson will cover

The Indicator interface

A small ABC: params (a dataclass), compute(ohlcv) -> Series/Frame, and a name/registry key. The same pattern as quantlab.strategies.ComboParams, generalized.

A registry & factory

Register indicators by name so a config file (or Optuna) can request 'rsi' with {'window': 14} generically — the foundation for parameter sweeps.

Multi-backend dispatch

One indicator, three engines: NumPy for single series, Polars .over('symbol') for universes, Numba for path-dependent ones — chosen automatically by input type/size.

Settings, validation, and warmup contracts

Every indicator declares its minimum history and validates params, so misconfiguration fails loudly, not silently.

Combining indicators generically

A combine() that takes a list of (indicator, settings) and produces a feature frame — the engine behind the capstone 'combine multiple indicators with custom settings'.
