scikit-learn for Trading

Applying ML to markets is mostly about not fooling yourself. We build leak-free features, label outcomes the smart way (triple-barrier), and validate with purged, embargoed cross-validation — the practices that separate honest research from data-snooping.

1. Features: reuse the registry, scale-free

Our quantlab.ml.make_features builds the feature matrix from the Module 7 registry, so features are declared as (name, settings) specs. Level-like features (SMA, ATR) are expressed as ratios to close so a $500 stock and a $20 stock become directly comparable — essential when a model trains across symbols and regimes.

2. Labeling: triple-barrier beats "did it go up?"

Naive labels ("up over the next 5 days?") ignore the path: a trade that craters 8% then closes +0.1% gets the same label as a smooth grind up — yet you'd have been stopped out of the first. The triple-barrier method labels each bar by the first of three barriers it touches: an upper (profit-take), a lower (stop-loss), or a vertical (time-out). Barriers are sized in volatility units so they adapt to regime.

🔬 Why volatility-scaled barriers

A fixed ±3% barrier is trivially hit in a volatile week and never hit in a calm one — so a fixed barrier secretly encodes the volatility regime into your labels. Sizing barriers as ±k·σ (σ = recent return volatility) makes "+2 sigma move" mean the same difficulty in every regime. Adaptive labels → a model that learns signal, not volatility.

3. The leak you can't see: train/test contamination

Two subtle leaks plague time-series ML. First, preprocessing leakage: fitting a scaler on all data lets test-set statistics bleed into training. The fix is a Pipeline, so scaling is fit only on each training fold. Second, label-overlap leakage: a triple-barrier label at t peeks up to t+horizon, which may land inside the test fold — so we purge overlapping training samples and embargo the ones right after the test fold.

4. Runnable: an honest end-to-end pipeline

Expected output

Dataset: (4072, 8) | positive rate: 46.3% Purged CV AUC: mean=0.545 folds=[0.582, 0.568, 0.523, 0.518, 0.536]
⚠️ AUC ≈ 0.5 is the honest baseline

Markets are close to efficient; an AUC of 0.52–0.56 on liquid daily data is a realistic, often-genuine edge — not a failure. Beware any tutorial reporting 0.9 AUC on price prediction: it's almost always leakage. The deliverable here is a pipeline that won't lie to you, so that when you do find edge, you can trust it.

Then convert the model's held-out probabilities into a signal with proba_to_signal and backtest it with backtest_signal. Compare the two labeling schemes by backtested Sharpe, not AUC — because PnL is the only metric that pays.
