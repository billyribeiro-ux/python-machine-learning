Numba: Path-Dependent Speed

Some indicators are inherently sequential — Supertrend, trailing stops, parabolic SAR — where each bar depends on the previous bar's output. You can't vectorize them away. Numba JIT-compiles the honest loop to machine code, giving you C speed without leaving Python.

1. When vectorization loses

Module 1 preached: delete your loops. That's right for the vast majority of indicators, where each output depends only on a fixed window of inputs. But a minority depend on prior outputs: a trailing stop's level today is "the higher of its level yesterday and a new candidate." There's no closed-form array expression for that without O(n²) tricks — the honest implementation is a loop. The skill is recognizing which regime you're in and not contorting a recurrence into a slow, "clever" vectorized form.

🎯 Two kinds of indicators

Window-dependent (SMA, RSI, z-score): output[t] = f(input[t-w:t]). → Vectorize (Module 1/3).
Path-dependent (Supertrend, trailing stops, SAR): output[t] = f(input[t], output[t-1]). → Loop, then JIT with Numba.

2. Numba in one minute

Decorate a function with @njit ("no-python JIT"). On first call, Numba compiles it to native code specialized to your argument types; every call after is C-fast. The rules: pass NumPy arrays and scalars (no Python objects/lists), and keep the body to plain numeric loops and math. The first call pays a one-time compilation cost.

3. Build Supertrend from scratch

Supertrend is an ATR-banded trailing trend filter. The bands ratchet — the lower band can only rise while in an uptrend, the upper band can only fall in a downtrend — and a close crossing the active band flips the regime. Each bar depends on the previous bar's band and direction, so it's a textbook path-dependent loop. Ours lives in quantlab/indicators/numba_indicators.py and degrades to pure Python if Numba isn't installed.

4. Turn it into a strategy signal

A Supertrend direction flip from -1 to +1 is a long entry; +1 to -1 is an exit. Because our backtest engine applies the one-bar execution delay, you can hand the raw direction straight to it.

🔬 parallel=True and guvectorize

Two more Numba tools for scale: @njit(parallel=True) with numba.prange spreads a loop across CPU cores (ideal for running a path-dependent indicator over thousands of symbols independently); and @guvectorize builds a generalized ufunc that broadcasts like a native NumPy operation. Reach for these when one symbol at C-speed still isn't enough and you need the whole universe in parallel.

🧱 Graceful degradation by design

Our module defines a maybe_njit shim: if Numba is installed it's the real @njit; if not, it's a no-op and the identical code runs in pure Python (slower, but correct). So the library is fast where it can be and works everywhere — a production-minded default that most indicator libraries skip.

🛠️ Try it

Write a Numba parabolic_sar(high, low, af=0.02, max_af=0.2) — another path-dependent classic where the acceleration factor steps up on each new extreme. Validate it against a slow pure-Python reference on 1,000 bars (they must match exactly), then time both. The speedup is your reward for understanding when the loop is unavoidable.
