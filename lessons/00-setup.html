Module 0 · Getting Started

Setup & the Principal-Engineer Mindset

Before a single indicator, we install everything correctly (including the famously fiddly TA-Lib), lay out a project the way a senior quant team would, and internalize the five habits that separate code that "runs" from code you'd actually trade real money on.

1. Why this course is different

Most tutorials teach you to call functions: talib.RSI(close, 14), done. That's enough to make a chart and dangerous enough to lose money. A principal engineer asks a different set of questions about that same line:

  • Is it correct? Does this RSI match Wilder's definition, or a subtly different one? How would I prove it?
  • Is it fast? Will it still run in milliseconds when I scan 5,000 symbols across 10 years of minute bars?
  • Does it leak the future? Does the value at bar t secretly depend on data from bar t+1? (This single bug invalidates more backtests than all others combined.)
  • Can I reproduce it? Same inputs, same outputs, forever — or does it depend on a library version, a random seed, or today's Yahoo data?
  • Can someone else trust it? Is there a test that fails loudly the day the behavior changes?

We will answer all five for everything we build. That is what "L7+" means here: not arcane syntax, but engineering judgement applied relentlessly to markets.

🎯 The five habits (our north star)

Vectorize — push loops into NumPy/Polars/C. Stabilize — choose numerically sound formulas. Don't peek — never let bar t see the future. Reproduce — pin versions, seed randomness, cache data. Test — every indicator and backtest has an assertion that guards it.

2. Installing Python and the toolkit

Use a dedicated environment so the course's pinned versions never collide with your other projects. We recommend conda/mamba for one reason that will save you an hour of pain: it can install the TA-Lib C library for you. (TA-Lib's Python package is a thin wrapper over a C library that must be compiled or installed separately — the #1 setup hurdle in all of Python quant.)

Option A — conda / mamba (recommended, handles TA-Lib)

Option B — pip / venv (you must install the TA-Lib C lib yourself)

⚠️ The TA-Lib trap

pip install TA-Lib fails with a compiler error if the underlying C library isn't present. The error mentions ta_libc.h not found. The fix is never "try pip again" — it's "install the C library first" (conda-forge is the least painful path on every OS). If you only need pure-Python indicators, you can skip TA-Lib entirely; our tests importorskip it.

The pinned requirements

Here is the requirements.txt the course ships with. Pinning major versions is a reproducibility habit: "works on my machine" becomes "works on every machine."

3. Project layout

A flat pile of notebooks does not scale. We use a small, conventional layout that separates the reusable library (quantlab/) from throwaway exploration and from tests. This is the same shape you'd find in a real quant shop, just smaller.

🔬 Why a package, not just notebooks?

Code you import is code you can test, version, reuse, and reason about. Notebooks are perfect for exploring and for this kind of narrated teaching, but the moment a function is good enough to depend on, it belongs in quantlab/ with a test. By the end of the course, quantlab/ is your personal quant platform; the notebooks are just how you got there.

4. The data layer: provider-agnostic from line one

Here's the most important architectural idea in the whole course, and we adopt it on day one: no lesson imports a data vendor SDK directly. Everything goes through a DataProvider interface. Today it's Yahoo Finance (free, no key); the day you switch to Alpaca or Polygon, you change one string and every line you ever wrote keeps working.

5. The one bug that ruins backtests: look-ahead bias

We introduce this now because it will haunt every later module. A bar for 2024-01-02 is only complete after the session ends. If your strategy uses bar t's close to make a decision and then assumes it traded at bar t's open, it has peeked at the future. The fix is a discipline we'll repeat constantly: a signal computed from data up to t can only act at t+1.

⚠️ Remember the rule

Decide on bar t, act on bar t+1. In pandas that's signal.shift(1). We packaged the safe version as quantlab.utils.forward_returns() for ML labels. Every backtest in this course honors this rule, and Module 10 builds a harness that makes it the default.

6. Reproducibility: seed it, pin it, cache it

Two runs of the same code should give the same answer. That means: seed every random number generator, pin library versions (done above), and cache market data so a re-run isn't at the mercy of Yahoo's mood. Our YahooProvider already caches to parquet — the second call is instant and offline.
