Module 9 · Backtesting

vectorbt: Combine Indicators at Scale

Our own engine taught you what a backtest is. vectorbt makes it industrial: it turns backtesting into array math so you can evaluate thousands of indicator/parameter combinations at once and get a stats grid. This is "combine multiple indicators with custom settings and come up with the stats" at full scale.

1. From our engine to vectorbt

In Module 0/10 our backtest_signal converts one signal into returns, honoring "decide on t, act on t+1." vectorbt does the same thing but vectorized across whole grids of parameters and assets simultaneously, with built-in fees, slippage, and a rich stats/plotting layer. The mental model is identical; the throughput is orders of magnitude higher.

🎯 The core call

vbt.Portfolio.from_signals(close, entries, exits, fees=...) takes boolean entry/exit arrays and produces a Portfolio object with .total_return(), .sharpe_ratio(), .max_drawdown(), and dozens more — and it broadcasts, so entries/exits can be 2-D (one column per parameter combo).

2. Sweep a single indicator's parameters

The classic: which SMA crossover is best? Instead of a loop you'd normally write, our helper (quantlab/backtest/vbt.py) runs every fast/slow pair and returns a stats table ranked by Sharpe.

4. IndicatorFactory: wrap your own indicators

vectorbt's IndicatorFactory turns any function into a parameterized, sweepable indicator with broadcasting. You can wrap the QuantLab indicators directly, so a sweep over, say, RSI window × z-score window runs as one vectorized operation rather than a Python loop.

⚠️ The best cell is probably luck

When you sweep 10,000 combinations and pick the highest Sharpe, you've run 10,000 hypothesis tests and kept the luckiest one. Its in-sample Sharpe is an upward-biased estimate of live performance — the multiple-testing problem. Module 10 covers walk-forward validation and the "deflated" Sharpe; Module 13 uses Optuna with proper out-of-sample checks. Never trade the top cell of a grid without out-of-sample confirmation.

🧱 Two engines, one philosophy

Use quantlab.backtest.engine when you want to understand a single strategy and assert invariants in tests; use vectorbt when you want to explore a huge parameter space fast. Both honor the one-bar execution delay. Keeping a transparent reference engine alongside the fast one is how you keep the fast one honest.

🛠️ Try it

Extend combo_sweep to also sweep the slow-SMA length (three nested parameters now). Render the resulting Sharpe surface as a heatmap with pf.sharpe_ratio().vbt.heatmap() or via pandas pivot + matplotlib. Notice whether good Sharpes cluster (a robust region — good) or appear as isolated spikes (overfit — bad). Reading that surface is a core quant skill.
