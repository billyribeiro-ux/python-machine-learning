Module 16 · Putting It Together

Streamlit Trading Dashboard

Everything you've built — data layer, indicators, backtest engine, scanners — becomes an interactive app in a few hundred lines. Streamlit turns Python scripts into web UIs, and because the logic already lives in quantlab, the app is just a thin, reactive shell.

1. Streamlit in one idea

A Streamlit app is a Python script that re-runs top-to-bottom on every interaction. Widgets (st.slider, st.text_input) return plain values; you compute with them and call st.line_chart, st.metric, st.dataframe to render. The mental model is "a script that paints itself" — no callbacks, no front-end code.

⚠️ Re-runs make caching essential

Because the whole script re-runs on every slider nudge, a naive app re-downloads data constantly. Wrap expensive, pure functions (data fetches) in @st.cache_data so they run once per unique input and return instantly thereafter. This single decorator is the difference between a sluggish app and a snappy one.

2. The QuantLab dashboard

Our app (app/streamlit_app.py) has six pages — a Custom Strategy builder, an honest Optimize page (Optuna with a hold-out and a live Deflated-Sharpe verdict), a walk-forward ML page, a combo Backtester, a universe Scanner, and an Indicator explorer — all driven by the same package functions you already know. Note how little app-specific code there is: the heavy lifting is all imports.

🧱 The dashboard is pure glue

The Optimize page calls quantlab.research.optimize_strategy and renders its best params, the in-sample→out-of-sample gap, the Deflated Sharpe, a trustworthy/over-fit badge, and the hold-out equity curve. The ML page calls quantlab.ml.walk_forward_predict for fully out-of-sample probabilities, maps them to a position, backtests the result, and shows feature importances. Both are a few dozen lines — because the rigor lives in the tested package, not the UI.

3. Run it

🔬 The scanner & indicator pages

The Scanner page calls quantlab.scanners.scan with a setup chosen from a dropdown and renders the ranked hits with st.dataframe. The Indicator page overlays SMAs and the Numba-computed supertrend line on price. Both are a dozen lines each — because the real work was done in Modules 7, 8, and 14. That is the dividend of building a clean package: the UI is almost free.

3b. The "Custom Strategy" page — build & test without writing code

The flagship page wires the Module 10 configurable backtester into the UI: pick a symbol and timeframe, list indicators as name:value lines, type a rule (or entry/exit expressions), and hit Run — you get live metrics, an equity curve vs buy & hold, drawdown, and recent positions. It reuses StrategyConfig, run_strategy, and parse_indicator_specs from the package, so the page is just glue.

🔬 Tested headlessly with AppTest

Streamlit ships streamlit.testing.v1.AppTest, which runs the app script without a browser so you can assert on widgets and outputs. We use it to verify the Custom Strategy page renders its metrics on Run, the entry/exit mode works, a bad expression surfaces a friendly st.error (instead of crashing), and the Scanner page runs. A dashboard is software too — it deserves tests.

4. Deployment notes

  • Secrets: when you move from Yahoo to a keyed provider, put credentials in .streamlit/secrets.toml and read them in your provider — never hard-code keys.
  • Caching: use @st.cache_data for data and @st.cache_resource for expensive objects (a trained model, a DuckDB connection).
  • Hosting: push to GitHub and deploy free on Streamlit Community Cloud, or run it on any VM with streamlit run. The app is provider-agnostic, so the same code runs locally on Yahoo and in production on your paid feed.
