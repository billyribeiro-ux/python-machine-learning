Module 1 · Data Foundations

NumPy to the Metal

Every fast thing in Python quant — pandas, Polars, TA-Lib, vectorbt, scikit-learn — is NumPy underneath. Understand the array's memory layout, broadcasting, and vectorization, and you can build indicators that are both correct and faster than the libraries. This is the bedrock; we pour it carefully.

1. What an ndarray really is

A Python list is a box of pointers to scattered objects. A NumPy ndarray is one contiguous block of raw bytes plus a little metadata describing how to interpret it: a dtype (how many bytes per number and how to read them), a shape, and strides (how many bytes to step to move one element along each axis). That's the whole magic: because the data is packed and uniform, the CPU can scream through it, and operations run in compiled C, not interpreted Python.

🔬 Why strides matter for indicators

Strides are how NumPy can give you a rolling window view of a price series without copying a single byte. We exploit that below to compute rolling statistics at C speed. Knowing strides exist is the difference between "I call rolling()" and "I know why it's fast and could write a faster one."

2. Vectorization: delete your for-loops

The cardinal sin of slow quant code is looping over bars in Python. Each iteration pays the interpreter tax — type checks, boxing, bytecode dispatch. Vectorization expresses the whole computation as array operations so the loop happens once, in C. Let's measure it on a dead-simple task: daily returns.

Typical output

loop : 280.0 ms vec : 3.0 ms speedup: 90x identical? True

Same answer, ~100× faster, and the vectorized version is shorter. The slicing trick p[1:] / p[:-1] — "tomorrow's array divided by today's array" — is the workhorse of return math. Internalize it.

3. Broadcasting: arithmetic between different shapes

Broadcasting is NumPy's rule for combining arrays of different shapes without writing loops or copying data. A scalar applies to every element; a (252,) vector applies down each column of a (252, 500) matrix. This is exactly the shape of a multi-asset return panel, so broadcasting is how you normalize 500 stocks at once.

⚠️ The axis mistake everyone makes

axis=0 means "collapse along rows" → you get one number per column. For a (days, assets) matrix that's a per-asset statistic. Getting this backwards silently computes cross-sectional stats when you wanted time-series stats (or vice versa) — the result still has a plausible shape, so it passes unnoticed. Always say the axis meaning out loud.

4. Rolling windows with zero copies (stride tricks)

Now the payoff. A rolling 20-day window over n bars is conceptually an (n-19, 20) matrix. Naively building it copies ~20× the data. NumPy's sliding_window_view instead returns a view using stride tricks — no copy — so you can apply any reduction (mean, std, max) along the window axis at full speed.

🔬 The even-faster trick for moving averages

For a moving average specifically, you can beat even the window view with a prefix sum: compute cumsum once, then every window sum is a single subtraction cumsum[t] - cumsum[t-w] — O(n) total, independent of window size. That's exactly how quantlab.indicators.sma is implemented. The window-view approach is O(n·w) but more general (works for std, max, custom funcs); the prefix-sum is the specialist that wins for sums/means. Knowing both, and when to use which, is the engineering.

🧱 Why ours can be "better than existing"

We match the standard libraries to floating-point precision — and we control the implementation: the prefix-sum SMA is O(n) regardless of window; the z-score guards divide-by-zero on flat windows (returns 0, not inf); the warmup is explicit NaN, never back-filled. When you own the code, you can fuse steps, drop redundant passes over the data, and JIT the recursive ones (Module 8). That's how a custom library outruns a general-purpose one on your workload.

6. Numerical stability: the silent killer

Floating-point math is not real-number math. Subtracting two nearly equal large numbers loses precision (catastrophic cancellation), and the textbook variance formula E[x²] − E[x]² is a classic offender. For prices in the hundreds this rarely bites; for some feature pipelines it absolutely does. The habit: prefer formulas that don't subtract big-from-big, and use log-returns for compounding.

⚠️ Variance went negative?

The naive formula can produce a negative "variance" here purely from rounding — an impossibility that crashes any later sqrt. This is why our rolling_std uses the window-view + NumPy's stable reduction rather than rolling a running sum-of-squares. When a number can't be wrong-but-plausible, make it impossible to be wrong.
